27. Interview Talking Points

Recruiter asks:

"Why Redis?"

Answer:

Redis was used as a message broker for asynchronous processing. Monitoring thousands of endpoints synchronously would block the API layer, so jobs are pushed into queues and processed by scalable worker instances.

"Why BullMQ?"

Answer:

BullMQ provides reliable background job execution with retries, delayed jobs, scheduling, and failure handling which are essential for monitoring systems.

"How would you scale?"

Answer:

By horizontally scaling worker instances, partitioning metrics storage, adding read replicas, caching analytics data, and distributing health checks across regions.

## So, final answer: **frontend or not?**

**Not right now.**

Build the backend first.

But make the backend **frontend-ready from day one**.

When the backend is solid, your designer can work on:

```text
React / Next.js
       ↓
PulseOps REST API
       ↓
Your backend
```

And you'll already have the difficult part—the actual engineering system—working.

One more blunt point: **don't spend three weeks polishing the PRD.** The PRD is useful, but recruiters won't hire you because your PRD is beautiful. They'll care that the repo contains a real worker system, queues, PostgreSQL, Redis, proper failure handling, tests, deployment, and that you can explain why you built it that way.

Your next move should be **implementation**, not more documentation.
